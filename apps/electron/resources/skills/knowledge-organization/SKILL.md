# Knowledge organization

Use the assigned files, sources and fields. Preserve source locations, links, dates, units and versions. Mark absent fields as unknown and list conflicting values separately. Deduplicate with retained provenance; do not silently rewrite conclusions while reorganizing them.

Choose a compact table, index, reference map or reusable file that downstream workers can consume. Check item counts, field completeness and path usability. Retain raw inputs when normalization or conversion could lose evidence. Extract only information needed for the current task.

In a Super Agent team, use the shared board for current coordination and `super_agent_library` for persistent memory or immutable archives. Search existing entries before adding a stable, supported fact, explicit preference, decision or reusable lesson; include evidence and preserve the current revision when updating. A partial summary is insufficient to replace an entire entry. Do not save credentials, unrelated personal information or unverified guesses as facts.

Archive a scoped version with the actual source path and version description; restore to a new destination and check the returned integrity evidence. A stored hash proves version identity, not factual correctness. Send only necessary IDs, versions and paths in handoff messages and report conflicts to the orchestrator.
